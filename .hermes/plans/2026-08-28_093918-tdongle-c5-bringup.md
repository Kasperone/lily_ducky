**Goal:** Take the never-built Phase 1–2 firmware to a verified-running
T-Dongle-C5: fix the known compile blocker, build both targets locally
(PlatformIO via uv), flash over USB Serial/JTAG, and prove every C5-relevant
subsystem (boot, SD, LCD, LED, button, WiFi C2 + REST, interpreter) works on
the real board.

**Architecture:** Single source tree, capability-flagged (`CFG_HAS_USB_HID=0`
on C5). Nothing in this plan touches HID-only code paths; the C5 exercises
interpreter + C2 + display + storage with typing as honest no-ops.

**Tech Stack:** PlatformIO (pioarduino fork 55.03.311, Arduino-ESP32 3.x),
TFT_eSPI, C/C++. Install PlatformIO with `uv tool install platformio`.

## Phase 2 — RESULTS round 1 (2026-08-29, user-reported symptoms)

User reported after flash: LCD black, LED solid white, button dead.
Root causes (verified against LilyGO factory firmware
Xinyuan-LilyGO/T-Dongle-C5 examples/Factory + LCD + LED):
1. **LCD backlight active-LOW** (d4b9d14): factory turns BL ON with
   `digitalWrite(PIN_LCD_BL, 0)`; we drove HIGH = OFF. Fixed via
   `-DTFT_BACKLIGHT_ON=LOW` (C5 env) + lcdInit() uses the macro.
2. **APA102 brightness bits were zero** (95f06c7): frame header built as
   0xE0000000 → 111|00000 = current sink disabled → LED dark at ANY colour
   (that also hid all button feedback). Fixed: brightness 10/31 (factory
   value); end frame now drives DATA high as the comment claimed.
3. **Button was actually working** — its feedback is LED/LCD only, both were
   broken. No code change needed; re-test with fixed output.
4. Bonus latent bug fixed in d4b9d14: INTERP_STOPPED ran blocking
   ledBlink() on EVERY loop() tick (perpetual 900 ms stalls, C2 + button
   starvation) — now one-shot blink + steady amber.
5. LCD rotation set to 3 (factory orientation).

## Phase 2 — RESULTS round 2 (2026-08-29, LED root cause RESOLVED)

LCD fix confirmed by user (dashboard correct). LED still hard white, button
"dead" (but serial log showed BTN=0 events + PRESSED lines — button works;
only its feedback channels were broken).

ROOT CAUSE of the white LED (proven with a /tmp/hwdiag diag firmware that
cycled R/G/B/OFF while alternating pin sets): the APA102's DI/CI are wired
to the chip's MTCK/MTDI pads (schematic V1.1 nets LED-DI/LED-CI = GPIO5/4).
At power-on the USB Serial/JTAG controller owns those pads; TDI idle-high +
TCK edges form exactly an APA102 white-bit stream, and GPIO writes never
reach the pads. `USB_SERIAL_JTAG.conf0.usb_jtag_bridge_en = 1` releases the
pads to the GPIO matrix → LED cycles correctly (user-confirmed red/green/
blue/off). CDC console, uploads and ROM boot unaffected.

Fix commit 40d37b8 (CFG_RELEASE_JTAG_LED_PINS, C5 only; cost = losing
OpenOCD-over-USB-JTAG on those pads, irrelevant here). Pushed.

### Task 11: Load payload onto SD via C2 API (doubles as API test)

The C5 has no USB MSC, so the card is written over the air.

**Step 1:** On this machine, join the AP:
`nmcli device wifi connect LilyC2 password quackquack` (or from user's
laptop — either works; if the VM has no WiFi, use the host/laptop and copy

**Step 2:** `curl http://192.168.4.1/api/status` →
expect `{"state":"idle","clients":N,"ap_ip":"192.168.4.1"}`
**Step 3:** Upload `payloads/hello.dd` as the boot default:
```bash
curl -X PUT -H "X-Auth-Token: <TOKEN>" -H "Content-Type: text/plain" \
  --data-binary @payloads/hello.dd http://192.168.4.1/api/payload/payload.dd
```
expect `OK`.
**Step 4:** Verify round-trip: `curl http://192.168.4.1/api/payload/payload.dd`
→ identical content; `curl http://192.168.4.1/api/payloads` → lists it.
**Step 5:** Negative auth test: same PUT without the token → expect `401`.

## Risks & open questions

| Risk | Mitigation |
|---|---|
| USB passthrough never works into this VM | Fallback: build here, user flashes from host with `pio` or esptool (`esptool.py write_flash` with the built bin) |
| pioarduino toolchain download huge/slow | Background run + notify; check disk first (Task 1) |
| SD init fails (SPI mode) | Reseat card; FAT32 format; pins already validated against LilyGO factory pin_config.h |
| LCD wrong offsets/colours | Flags already set (`GREENTAB160x80`, BGR, INV ON) — if wrong, compare with LilyGO factory firmware User_Setup |
| More compile errors under Arduino-ESP32 3.x | Budgeted fix loop in Task 3; ask user after 3 tries per file |
| WiFi 6 AP not joinable by older client hardware | C5 AP falls back fine in practice; if not, test from a phone |
